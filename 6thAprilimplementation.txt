## UNIT 3: HR ADK AGENTS (BUILD)
=============================================================================

Based on: gemini enterprise implementation plan.md (47KB)
          gemini enterprise deployment plan.md (31KB)

Plan scope: 82 HR & PeopleOps agents from the Agentic Transformation Field Kit
            (authored by Shanky Ram, Principal Architect, Google Cloud APAC)
            This batch implements 6 priority ADK agents (Layer 3 & 4).

### Agent 1: Policy Q&A Assistant
  - File: backend/hr_agents/policy_qa_agent.py
  - Type: RAG-grounded Q&A agent (Layer 1+)
  - RAG Corpus: projects/general-ak/locations/us-central1/ragCorpora/2305843009213693952
  - Model: gemini-2.5-flash
  - Tools: get_leave_balance, check_policy_applicability
  - Purpose: Answer employee HR policy questions; cites policy name + effective date
  - Access: All employees (read-only, no PII)

### Agent 2: 1:1 Meeting Prep Agent
  - File: backend/hr_agents/meeting_prep_agent.py
  - Type: HRIS + BigQuery integration agent (Layer 3, medium complexity)
  - Model: gemini-2.5-flash
  - Tools: get_employee_profile, get_okr_progress, get_recent_feedback, get_flight_risk
  - Purpose: Prepare managers for 1:1 meetings with OKR progress, feedback themes,
             and attrition risk signals (risk level only — never raw score)
  - Access: HRBPs and managers (scoped to direct reports)

### Agent 3: Resume Screening Agent (HIGH COMPLEXITY)
  - File: backend/hr_agents/resume_screening_agent.py
  - Type: Vertex AI text-embedding-005 semantic scoring (Layer 3)
  - Model: text-embedding-005 (embeddings) + gemini-2.5-flash (analysis)
  - Tools: get_job_requirements, get_applicant_pool, score_candidate_fit,
           write_screening_note, get_diversity_funnel_metrics
  - Purpose: Score candidates against job descriptions using vector similarity
  - Score formula: semantic cosine similarity (0-100) → shortlist if >= 70
  - Diversity guardrail: flags shortlists with <30% female representation
  - ATS integration: writes structured screening notes to Greenhouse
  - Access: Recruiters only

### Agent 4: Onboarding Orchestration Agent (HIGH COMPLEXITY)
  - File: backend/hr_agents/onboarding_agent.py
  - Type: Multi-step orchestrator with ServiceNow integration (Layer 3)
  - Model: gemini-2.5-flash
  - Tools: get_onboarding_checklist, get_onboarding_completion,
           raise_it_provisioning_ticket, send_welcome_message
  - Purpose: End-to-end employee onboarding task management
  - Integrations: ServiceNow (IT provisioning tickets), HRIS (employee profile),
                  BigQuery (onboarding task templates), email comms system (stubs)
  - Role types: technology, operations, frontline, leadership
  - Access: HR Ops, HRBPs, new hires

### Agent 5: Talent Acquisition Orchestrator (HIGH COMPLEXITY)
  - File: backend/hr_agents/talent_acquisition_orchestrator.py
  - Type: Multi-agent orchestrator using agent_tool (Layer 3)
  - Model: gemini-2.5-flash
  - Tools: validate_requisition, agent_tool(resume_screening_agent),
           schedule_interviews, get_sourcing_channel_performance
  - Sub-agents: Resume Screening Agent (delegated via agent_tool)
  - Purpose: End-to-end talent acquisition workflow
    → Requisition validation (headcount approval, comp band, HRIS sync)
    → Candidate screening (delegated to Resume Screening Agent)
    → Interview scheduling (Google Calendar integration stub)
    → Pipeline analytics and sourcing channel performance
  - Access: Recruiters, Hiring Managers, TA leadership

### Agent 6: Workforce Analytics Agent (HIGH COMPLEXITY)
  - File: backend/hr_agents/workforce_analytics_agent.py
  - Type: NL→SQL BigQuery agent (Layer 4 — Data Agent)
  - Model: gemini-2.5-flash
  - Tools: query_workforce_data, get_attrition_summary, get_headcount_by_dimension
  - Purpose: Answer workforce analytics questions in natural language
  - BigQuery dataset: hr_analytics (mapped from hr_data schema in plan)
  - Tables covered: employees, compensation, performance, attrition_history,
                    attrition_predictions, leave, requisitions, candidates,
                    okrs, learning + 2 onboarding tables
  - Safety: SELECT-only (blocks INSERT/UPDATE/DELETE/DROP/CREATE/TRUNCATE/MERGE)
  - PII guardrail: individual salary data blocked unless CHRO or Comp & Ben Manager
  - Access: People Analytics, HRBPs (dept-scoped), CHRO (full view)

**Shared Utilities:**
  - backend/hr_agents/shared/auth.py (Secret Manager credential fetcher)
  - backend/hr_agents/shared/hris_client.py (Workday/SAP HRIS stub)
  - backend/hr_agents/shared/ats_client.py (Greenhouse ATS stub)
  - backend/hr_agents/shared/bq_client.py (BigQuery read-only, SELECT-only guard)
  - backend/hr_agents/shared/servicenow_client.py (ServiceNow stub)

**Test Suite:**
  - backend/hr_agents/tests/test_agents.py
    Tests: meeting_prep, resume_screening, workforce_analytics, prompt_injection guard
    Runner: google.adk.runners.InMemoryRunner + InMemorySessionService

**Model Armor (FSI/Banking compliance):**
  All ADK agents configured with ModelArmorConfig:
    block_sensitive_pii=True    (SSN, account numbers)
    block_harmful_content=True
    detect_prompt_injection=True
    audit_logging=True          (Cloud Audit Logs — regulatory requirement)
    data_residency_region="IN"  (for Indian banks, RBI data residency)
